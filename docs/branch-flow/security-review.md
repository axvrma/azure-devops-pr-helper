# Branch Flow security and privacy review

Reviewed locally on 2026-10-26. Scope: Branch Flow, the shared Azure/PR boundary, and relevant legacy webview/analytics integration. This is an engineering review, not an independent penetration-test certification.

| Boundary / threat | Implemented control | Automated evidence |
| --- | --- | --- |
| Imported JSON redirects a PAT | HTTPS URL validation; graphs must match the configured organization or the user must explicitly authorize another organization through the native context picker. Webview edits cannot change repository context. | schema, URL, native-panel tests |
| Credentials leak into the graph/webview | SecretStorage stays in host; only presence flags in legacy forms. Strict graph/message fields; no freeform payload passthrough. PR URLs constructed from approved context, not response links. | panel canary, schema and browser tests |
| Webview injection / arbitrary network | React renders labels as text, script nonces, bundled local resources with restricted roots, default-src none, connect-src none, base-uri none, form-action none. Zod jitless disables eval probing. React Flow needs positional style attributes, allowed via style-src-attr; inline style blocks/scripts remain denied. | production-bundle Chromium CSP test, unsafe-label test |
| Shell/ref injection | spawn('git', argument arrays), no shell, SHA-only operation arguments, branch/schema checks, time/output limits. Legacy synchronous helpers now have time/output limits and validate target refs. | real Git, schema and malicious-ref tests |
| User checkout damage / Git hook execution | Separate temporary repository, no templates/remotes, sanitized environment and config, disabled hooks/signing/rerere/protocols/updateRefs/autostash. No fetch. | real Git tests with dirty checkout, hook config and updateRefs enabled |
| False conflict / green | Exact SHAs, ancestry proof, separate operation modes; errors unknown/error, active/completed PR distinction, stale-head guards, genuine simulation conflict paths. | status, Git, coordinator and race tests |
| Accidental remote writes | Only explicit existing PR form submission creates PRs. Shared in-flight lock and exact active pair lookup; reads retried, writes never retried. No merge/push/rebase remote API exists. | PR and Axios transport tests |
| Malicious Azure responses | Response schemas, encoded URL components, request/body/response limits, no redirects, safe generic HTTP errors without request configs or bodies. | mock HTTP tests |
| Old responses replace fresh validation | Abort signals, generation guard, per-document service, topology changes cancel obsolete runs, refs rechecked at the end. | cancellation/race tests |
| Local concurrent overwrite | Content stamps, sibling exclusive lock, second pre-replace check, fsync/rename, watcher banner, recovery baseline stamp retained, explicit nonlocal-write refusal. | real-file and crash-backup tests |
| Private telemetry / errors | No Branch Flow events. Central allowlist drops repo/branch/model/content strings and reduces legacy error strings to a fixed category. Both VS Code and extension telemetry switches checked before capture/identify. AI and Azure error handlers no longer log raw bodies. | privacy allowlist and safe-error tests |

The remaining legacy PR/Settings/sidebar HTML uses nonce scripts and inline CSS, with resource roots restricted to the shared local `media/ui` styles; it was retained to limit regression scope. Existing history labels are escaped before HTML interpolation. Runtime message handlers now reject malformed envelopes and contain failures, and PR submission has its own strict schema. Existing AI requests are optional user-invoked operations and may intentionally send local commit/diff context to the chosen provider; Branch Flow never uses AI. Provider model availability and live credential behavior still require manual regression checks.

Network risks: an explicitly approved HTTPS server receives the configured PAT; the extension cannot independently establish that the server is owned by the user. HTTP organization endpoints are now refused, including on-premises HTTP installations; use HTTPS. System/enterprise certificate and proxy configuration is respected by Axios. Redirects are refused to prevent credential forwarding.

Local risks: saved graph/backup contents are user data and may include private labels/paths, so they must be protected like project documents. A third-party file writer that ignores locks can race the final stamp check; no cross-process filesystem transaction is claimed. Lock remnants are not automatically deleted. Hard process/OS termination can leave a simulation temp directory (containing checked-out source); normal failures and cancellation clean it up. No source content is stored in graph JSON.

Dependency audit: current locked dependencies were checked with npm audit, including dev tooling, and reported zero vulnerabilities. @vscode/vsce's identity dependency is pinned to 4.13.0 to avoid a current MSAL 6 authorization-code advisory, and its MSAL UUID helper is pinned to UUID 11's patched CommonJS-compatible API. These are packaging-only overrides. Review and remove the overrides when upstream supplies a safe compatible dependency chain; do not use `npm audit fix --force` blindly. Runtime packages and licenses are collected in THIRD_PARTY_NOTICES.md.
